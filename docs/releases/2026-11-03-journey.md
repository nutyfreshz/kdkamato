# Journey, completion and calories — 3 November 2026

The previous production page fixed its title and data range to 28 days, highlighted one improving lift, and offered subjective adherence choices without a numeric food tracker. This release uses a neutral Thai title and selectable 7/30/90-day windows (default 30), summarizes outcomes across comparable program items, and exposes recorded sets and daily calories alongside their denominators and targets.

## Definitions

- Exercise comparison: first set on the first and last eligible dates of the same program/item/exercise. Equal known RIR and equal GOOD/OK control are required to classify progression. More load with fewer reps, or different effort/control, remains mixed. The UI shows load and reps together; unlike exercises are never averaged into a strength number. Missing external load remains visible in source records but is not a claimed strength increase.
- Strength overview: improved items / comparable items. Declining performance, recent problems and poor recovery take precedence over a positive story. A new trainee uses these same rules; account IDs, demo metadata and persona labels are not evaluation inputs. These are transparent record comparisons, not validated causal or body-composition measurements.
- Training completion: valid, unique recorded working sets / all prescribed sets for the recorded training day of the current program, capped per item. Missing exercises contribute zero to that day's denominator. Days with no logs have unknown attendance; this is not an attendance, form-quality or weekly schedule percentage.
- Food tracker: user-entered daily total calories, not a food database or measured intake. Current program target and estimated maintenance ranges are displayed. A server-controlled first-entry snapshot preserves each day's applicable target. Missing calories are unknown; days without a valid target are excluded from the in-range denominator. The server does not backfill a new program's target onto earlier dates.
- Daily history: a new date creates a record; saving the same workout item or nutrition day again updates that date. All workout sets remain inspectable. Subjective legacy check-ins remain optional and separate; numeric metrics are not arbitrarily mapped into old adherence categories or PRO decisions.

## Database and compatibility

Additive migration `20261103013019_journey_measured_progress_v1.sql` adds `nutrition_daily_logs`, owner-only select/insert/update RLS and an invoker trigger that guards dates, ownership and target snapshots. Anonymous access and authenticated deletion are denied. Existing private workout-history RPC retains its owner predicate and authenticated-only execution, expanding its bounds to 90 days / 5,000 most recent rows. No user workout/check-in history is overwritten and no program is changed automatically.
